## Marker interfaces

Models must be `partial` and implement one or more of the following interfaces to trigger code generation.

| SQL Server        | PostgreSQL           | Generates                                                       |
|-------------------|----------------------|-----------------------------------------------------------------|
| `ISqlMapper`      | `INpgsqlMapper`      | Reader mapper (`Map(reader)`) + typed parameter factory methods |
| `ISqlDomainModel` | `INpgsqlDomainModel` | Everything above + CRUD operations + batch commands             |
| `ISqlBulkModel`   | `INpgsqlBulkModel`   | Everything above + bulk insert/update/delete                    |

Each interface inherits from the one above. A single DTO can implement interfaces for both providers simultaneously.

```csharp
// SQL Server only
public sealed partial record Order(Guid Id, string ProductName, Guid UserId) : ISqlDomainModel;

// Dual-provider
public sealed partial record User(Guid Id, string Name, string Email) : ISqlBulkModel, INpgsqlBulkModel;
```

## Profiles

A profile is required for every `ISqlDomainModel` / `ISqlBulkModel` / `INpgsqlDomainModel` / `INpgsqlBulkModel` per provider, even if all properties have default mappings. Configuration is read at compile time by the generator — the constructor is never executed at runtime.

**Mapper-only DTOs** (implementing only `ISqlMapper` / `INpgsqlMapper`) do not need a profile. `Map(reader)` and the `CreateParameter*` factories are generated by convention. A property that needs mandatory metadata the convention cannot supply gets **no** `CreateParameter*` factory (`Map` is unaffected):

| Provider   | No factory generated without a profile for…                               |
|------------|----------------------------------------------------------------------------|
| SQL Server | `string`, `byte[]` (size required), `decimal` (precision + scale required) |
| PostgreSQL | `string`, `decimal` (DB type required)                                     |

Add a profile if you need those factories.

Exactly one profile per DTO per provider is allowed. Profile constructor statements must be plain `RuleFor(...)`, `Table(...)`, `Schema(...)`, `Key(...)` and `Identity(...)` calls with compile-time constant arguments (see [diagnostics](diagnostics.md)). Call `Key(...)` once per column for a composite key.

```csharp
public sealed class UserProfile : SqlProfile<User>      // or NpgsqlProfile<User>
{
    public UserProfile()
    {
        // profile-level settings and property rules go here
    }
}
```

### Profile-level settings

| Method                  | Default                                    | Notes                                          |
|-------------------------|--------------------------------------------|------------------------------------------------|
| `Table("name")`         | Class name pluralized                      | Custom table name                              |
| `Schema("name")`        | `dbo` (SQL Server) / `public` (PostgreSQL) | Custom schema                                  |
| `Key(x => x.Prop)`      | Property named `Id`                        | Primary key override                           |
| `Identity(x => x.Prop)` | —                                          | Identity / SERIAL column; excluded from INSERT |

### Property configuration

```csharp
RuleFor(x => x.PropertyName)
    .VarChar(50)               // type + size in one call
    .Name("ColumnName")        // optional column name override
    .ReadOnly()                // optional — exclude from writes
    .ConcurrencyToken()        // optional — optimistic concurrency
    .DefaultValue("GETUTCDATE()");     // optional — DDL DEFAULT clause
```

Common modifiers available on all properties:

| Method                       | Notes                                                               |
|------------------------------|---------------------------------------------------------------------|
| `.Name(string)`              | Override DB column name (default: property name)                    |
| `.Nullable()` / `.NotNull()` | Explicit nullability (inferred from `?` by default)                 |
| `.ReadOnly()`                | Excluded from INSERT/UPDATE/bulk writes; included in DDL and mapper |
| `.DefaultValue(sqlExpr)`     | Emitted as `DEFAULT {sqlExpr}` in the column DDL (`"GETUTCDATE()"` / `"now()"`). A leading `DEFAULT` keyword is accepted for backward compatibility |
| `.ConcurrencyToken()`        | See [Concurrency tokens](#concurrency-tokens)                       |

### SQL Server types

| Shorthand                        | Equivalent            | Use for                      |
|----------------------------------|-----------------------|------------------------------|
| `VarChar(n)`                     | `SqlDbType.VarChar`   | ASCII strings                |
| `NVarChar(n)`                    | `SqlDbType.NVarChar`  | Unicode strings              |
| `Char(n)`                        | `SqlDbType.Char`      | Fixed-length ASCII           |
| `NChar(n)`                       | `SqlDbType.NChar`     | Fixed-length Unicode         |
| `VarBinary(n)`                   | `SqlDbType.VarBinary` | Binary data                  |
| `Decimal(p, s)`                  | `SqlDbType.Decimal`   | Decimal with precision/scale |
| `Type(SqlDbType.X)` + `.Size(n)` | —                     | Escape hatch for any type    |

`Guid`, `bool`, numeric types, `DateTime`, `DateTimeOffset` have default mappings — no configuration needed.  
**On SQL Server, `string`, `decimal` and `byte[]` require explicit configuration** (AG004 / AG005 / AG006).

### PostgreSQL types

| Shorthand                           | Equivalent             | Use for                            |
|-------------------------------------|------------------------|------------------------------------|
| `VarChar(n)`                        | `NpgsqlDbType.Varchar` | Variable-length strings with limit |
| `Text()`                            | `NpgsqlDbType.Text`    | Unbounded strings                  |
| `Char(n)`                           | `NpgsqlDbType.Char`    | Fixed-length strings               |
| `Bytea()`                           | `NpgsqlDbType.Bytea`   | Binary data                        |
| `Varbit(n)`                         | `NpgsqlDbType.Varbit`  | Bit strings                        |
| `Decimal(p, s)`                     | `NpgsqlDbType.Numeric` | Numeric with precision/scale       |
| `Type(NpgsqlDbType.X)` + `.Size(n)` | —                      | Escape hatch for any type          |

**Required configuration on PostgreSQL:**
- `string` needs no rule. It defaults to `text`, which is PostgreSQL best practice; `varchar` and `text` are binary-coercible, so there is no performance difference. Use `VarChar(n)` only when you want a length constraint, and give it a size (AG004).
- `decimal` needs `Decimal(p, s)` (AG005).
- `byte[]` defaults to `bytea`.

## Querying

All query methods auto-open the connection if it is not already open (and leave it open — see [Runtime behaviour](#runtime-behaviour)).

> Columns are matched **by name**, once per result set, so column order does not matter and extra columns are ignored. See [Runtime behaviour](#column-order-and-the-generated-mapper).

### `QueryAsync<T>`

Returns `List<T>`. Requires `ISqlMapper` / `INpgsqlMapper`.

```csharp
// No parameters
var users = await connection.QueryAsync<User>("SELECT * FROM Users", ct);

// Single parameter
var orders = await connection.QueryAsync<Order>(
    "SELECT * FROM Orders WHERE UserId = @UserId",
    OrderSql.CreateParameterUserId(userId), ct);

// Multiple parameters
var results = await connection.QueryAsync<Order>(
    "SELECT * FROM Orders WHERE UserId = @UserId AND Status = @Status",
    [OrderSql.CreateParameterUserId(userId), OrderSql.CreateParameterStatus("active")],
    ct);
```

### `QueryFirstOrDefaultAsync<T>`

Returns `T?`. Same overloads as `QueryAsync<T>`.

### `QueryMultiAsync`

Returns the raw `SqlDataReader` / `NpgsqlDataReader` for multi-result-set queries.

```csharp
await using var reader = await connection.QueryMultiAsync(
    "SELECT * FROM Users; SELECT * FROM Orders", ct);

var users  = await reader.QueryAsync<User>(ct);   // advances to the next result set itself
var orders = await reader.QueryAsync<Order>(ct);
```

The reader extensions `QueryAsync<T>` and `QueryFirstOrDefaultAsync<T>` call `NextResultAsync` after consuming their result set. **Do not** call `NextResultAsync` yourself between them, or you will skip a result set. You own the returned reader, so dispose it.

All three query methods accept an optional `CommandType`, `SqlTransaction`, and `commandTimeout`.

## Commands

Available when the model implements `ISqlDomainModel` / `INpgsqlDomainModel`.

| Method                            | Returns             | Notes                                                  |
|-----------------------------------|---------------------|--------------------------------------------------------|
| `InsertAsync(model, ct)`          | `int` rows affected |                                                        |
| `InsertAsync(List<T>, ct)`        | `int` rows affected | Multi-row; SQL Server splits into chunks — see [limits](#parameter-and-row-limits-sql-server) |
| `InsertAndReturnAsync(model, ct)` | `T`                 | Returns populated row; see [limitations](#limitations) |
| `UpdateAsync(model, ct)`          | `int` rows affected | Throws `AdoGenConcurrencyException` if token mismatch  |
| `UpsertAsync(model, ct)`          | `int` rows affected | Does not enforce concurrency token                     |
| `DeleteAsync(model, ct)`          | `int` rows affected | Throws `AdoGenConcurrencyException` if token mismatch  |
| `TruncateAsync<T>(ct)`            | `int` rows affected |                                                        |
| `CreateTableAsync<T>(ct)`         | `void`              | DDL — creates the table from profile metadata          |

All methods accept an optional `SqlTransaction` / `NpgsqlTransaction` and `commandTimeout`.

`InsertAndReturnAsync` internals:
- SQL Server: `INSERT … OUTPUT INSERTED.*`
- PostgreSQL: `INSERT … RETURNING *`

`UpsertAsync` internals:
- SQL Server: `INSERT … SELECT … WHERE NOT EXISTS (SELECT 1 … WITH (UPDLOCK, HOLDLOCK) WHERE pk = @pk); IF @@ROWCOUNT = 0 UPDATE …`. The key-range lock makes concurrent upserts of the same key safe. For an identity key, the INSERT path lets the database generate a new key.
- PostgreSQL: `INSERT … ON CONFLICT (pk) DO UPDATE SET …`. When the key includes an `Identity(...)` column, `MERGE` is used instead (**requires PostgreSQL 15+**); the INSERT path lets the database generate the key.

Models whose every column is part of the key (e.g. a join table) are supported: `UpdateAsync` is an existence-checking no-op that returns the matched row count, and `UpsertAsync` only inserts when the row is missing.

## Patch (partial update)

The generator emits a `{Model}Patch` class for every `ISqlDomainModel` / `INpgsqlDomainModel`. A patch carries only the columns you explicitly set — unset columns are **not** included in the UPDATE statement.

```csharp
// Only Email is updated; Name is unchanged in the database
var patch = new UserPatch(userId).WithEmail("new@example.com");
int affected = await connection.PatchAsync(patch, ct);

// Fluent or property-setter style — both work
var patch2 = new UserPatch(userId) { Email = "new@example.com" };

// Returns 0 (no-op) when no columns are set
var noop = new UserPatch(userId);
int affected = await connection.PatchAsync(noop, ct);   // 0
```

`PatchAsync` accepts an optional transaction and `commandTimeout`.

**Optimistic concurrency (opt-in):** for a model with a concurrency token, the patch class exposes `WithExpected{Token}(...)` instead of a setter for the token:

```csharp
// int / long token: only applies if Version is still 3, and bumps it to 4
await connection.PatchAsync(new OrderPatch(id).WithProductName("X").WithExpectedVersion(3), ct);

// Guid token: caller supplies the expected and the new value
await connection.PatchAsync(new Order2Patch(id).WithProductName("X").WithExpectedVersion(current, Guid.NewGuid()), ct);
```

With `WithExpected…` set, 0 affected rows throws `AdoGenConcurrencyException`. Without it, the patch targets the key only, the token is left untouched, and a missing row simply returns 0.

## Delete by IDs

### Single-key models

Deletes a list of records in one round-trip.
- SQL Server: `DELETE t FROM … JOIN (VALUES (@p0),(@p1),…)` — one parameter per id, subject to the [2100-parameter / 1000-row limits](#runtime-behaviour).
- PostgreSQL: `DELETE … WHERE pk = ANY(@ids)` — a single array parameter.

```csharp
// Explicit key type
await connection.DeleteAsync<User, Guid>(listOfIds, ct);

// Convenience overloads for common key types (Guid, long, int, short, decimal, string)
await connection.DeleteAsync<User>(listOfGuids, ct);
```

### Composite-key models

Uses a VALUES + JOIN pattern.

```csharp
await connection.DeleteAsync(listOfModels, ct);
```

## Exists

### Single-key models

```csharp
bool exists = await connection.ExistsAsync<User>(userId, ct);

// Explicit key type
bool exists = await connection.ExistsAsync<User, Guid>(userId, ct);
```

### Composite-key models

```csharp
bool exists = await connection.ExistsAsync(model, ct);
```

Uses `SELECT TOP(1) 1 … WHERE pk = @pk` (SQL Server) / `SELECT 1 … WHERE pk = @pk LIMIT 1` (PostgreSQL).

## Batching

Batch multiple typed operations into a single round-trip. Available on `SqlBatch` (SQL Server) and `NpgsqlBatch` (PostgreSQL).

```csharp
await using var batch = connection.CreateBatch();

batch.Insert(order1);
batch.Update(order2);
batch.Delete(order3);
batch.Upsert(order4);

await batch.ExecuteNonQueryAsync(ct);
```

**`InsertAndReturn` in a batch** — use `ExecuteReaderAsync` to read back server-generated values:

```csharp
batch.InsertAndReturn(newOrder1);
batch.InsertAndReturn(newOrder2);

await using var reader = await batch.ExecuteReaderAsync(ct);

// The reader extension reads the row and advances to the next result set
var first  = await reader.QueryFirstOrDefaultAsync<Order>(ct);
var second = await reader.QueryFirstOrDefaultAsync<Order>(ct);

// Or, manually: position on the row before calling Map
// await reader.ReadAsync(ct); var row = Order.Map(reader); await reader.NextResultAsync(ct);
```

You can freely mix AdoGen-managed commands with custom `SqlBatchCommand` / `NpgsqlBatchCommand` instances in the same batch.

## Bulk operations

Available when the model implements `ISqlBulkModel` / `INpgsqlBulkModel`.

```csharp
var bulk = new UserBulk(capacity: 500);          // UserNpgsqlBulk for PostgreSQL
bulk.AddRange(usersToInsert);
bulk.UpdateRange(usersToUpdate);
bulk.UpsertRange(usersToUpsert);
bulk.RemoveRange(usersToDelete);

await using var connection = new SqlConnection(connectionString);
await connection.OpenAsync(ct);
await using var tx = (SqlTransaction)await connection.BeginTransactionAsync(ct);

BulkApplyResult result = await bulk.SaveChangesAsync(connection, tx, ct);
Console.WriteLine($"Inserted: {result.Inserted}, Updated: {result.Updated}, Deleted: {result.Deleted}");

await tx.CommitAsync(ct);
```

SQL Server uses `SqlBulkCopy` via a temp table. PostgreSQL uses `COPY` (binary format) via Npgsql.

## Scalar & execute helpers

### `ExecuteAsync`

Runs a non-query statement and returns affected row count.

```csharp
int rows = await connection.ExecuteAsync("DELETE FROM Logs WHERE CreatedAt < @cutoff", param, ct);
```

### `ExecuteScalarAsync<T>`

Returns a single scalar value.

```csharp
int count = await connection.ExecuteScalarAsync<int>("SELECT COUNT(*) FROM Users", ct);          // SQL Server
long pgCount = await connection.ExecuteScalarAsync<long>("SELECT count(*) FROM \"Users\"", ct);  // PostgreSQL: count(*) is bigint
```

The value is **cast** (unboxed), not converted. `T` must exactly match the provider's CLR type for the column. For example, PostgreSQL `count(*)` returns `long`, so `ExecuteScalarAsync<int>` throws `InvalidCastException`. A missing row or a `NULL` / `DBNull` result returns `default(T)`.

### `QueryScalarAsync<T>`

Returns `List<T?>` — all values from the first column.

```csharp
var ids = await connection.QueryScalarAsync<Guid>("SELECT Id FROM Users WHERE Active = 1", ct);
```

### `QueryScalarFirstOrDefaultAsync<T>`

Returns the first value from the first column, or `default(T)`.

```csharp
var name = await connection.QueryScalarFirstOrDefaultAsync<string>(
    "SELECT Name FROM Users WHERE Id = @Id",
    UserSql.CreateParameterId(userId), ct);
```

All scalar/execute methods have three overloads: no parameters, single `SqlParameter` / `NpgsqlParameter`, and `IEnumerable<SqlParameter>` / `IEnumerable<NpgsqlParameter>`.

## Concurrency tokens

Mark one column per model as the optimistic concurrency token:

```csharp
RuleFor(x => x.Version).ConcurrencyToken();   // int, long, or Guid
```

**Behaviour:**

| Token type     | UPDATE WHERE clause        | UPDATE SET side-effect                                    |
|----------------|----------------------------|-----------------------------------------------------------|
| `int` / `long` | `AND [Version] = @Version` | `[Version] = @Version + 1` (auto-bump)                    |
| `Guid`         | `AND [Version] = @Version` | None — caller sets new value before calling `UpdateAsync` |

- `DeleteAsync` also adds `AND [Version] = @Version` to the WHERE clause.
- If 0 rows are affected, `AdoGenConcurrencyException` is thrown.
- `UpsertAsync` does **not** enforce the concurrency token — use `UpdateAsync` if you need optimistic locking.
- `PatchAsync` enforces it only when `WithExpected{Token}(...)` is called — see [Patch](#patch-partial-update).

---

## Read-only columns

```csharp
RuleFor(x => x.CreatedAt).ReadOnly().DefaultValue("GETUTCDATE()");   // PostgreSQL: "now()"
```

- Excluded from INSERT, UPDATE, `PatchAsync`, and bulk-write column lists.
- Still emitted in `CREATE TABLE` DDL.
- Still read back by the generated `Map(reader)` method.

Typical use cases: database-generated timestamps, computed columns, audit fields.

## Generated output

For a model named `User` implementing `ISqlBulkModel` and `INpgsqlBulkModel`:

| File                      | Contents                                                                                                                                                                       |
|---------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `User.Mapper.Sql.g.cs`    | `partial record User` with `static User Map(SqlDataReader)` + `static partial class UserSql` with `CreateParameter*` factory methods                                            |
| `User.Domain.Sql.g.cs`    | SQL text constants and the CRUD implementation (`InsertAsync`, `InsertAsync(List<T>)`, `InsertAndReturnAsync`, `UpdateAsync`, `UpsertAsync`, `DeleteAsync`, `TruncateAsync`, `CreateTableAsync`, `ExistsAsync`, batch commands), plus `UserPatch` and `PatchAsync` |
| `User.Bulk.Sql.g.cs`      | `UserBulk` — bulk add/update/remove + `SaveChangesAsync`                                                                                                                       |
| `User.Mapper.Npgsql.g.cs` | `Map(NpgsqlDataReader)` + `static partial class UserNpgsql` with `CreateParameter*` factories                                                                                  |
| `User.Domain.Npgsql.g.cs` | PostgreSQL CRUD + `UserPatch` (PostgreSQL namespace)                                                                                                                           |
| `User.Bulk.Npgsql.g.cs`   | `UserNpgsqlBulk`                                                                                                                                                               |

To inspect the generated files, build with:

```bash
dotnet build -p:EmitCompilerGeneratedFiles=true -p:CompilerGeneratedFilesOutputPath=/tmp/adogen-gen
```

Or set `<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>` in the project file. Files appear under `obj/.../generated/AdoGen.Generator/`.

None of the generated code uses reflection, expression trees, or dynamic IL.

## Runtime behaviour

Behaviour that is not obvious from the method signatures.

### Column order and the generated mapper

`QueryAsync<T>` / `QueryFirstOrDefaultAsync<T>` resolve column ordinals **by name, once per result set** (`T.GetOrdinals(reader)`), then call `T.Map(reader, ordinals)` per row. Column order is therefore irrelevant, extra columns are ignored, and different queries may select columns in different orders.

When calling the generated mapper yourself, resolve the ordinals once per reader and reuse them: `var ord = User.GetOrdinals(reader); while (await reader.ReadAsync(ct)) list.Add(User.Map(reader, ord));`. The single-argument `Map(reader)` resolves ordinals on every call.

### Connection lifetime

Every extension method opens a closed connection automatically and **never closes it**. Dispose the connection yourself (`await using var connection = …`).

### Parameter and row limits (SQL Server)

`InsertAsync(List<T>)` and `DeleteAsync(List<TKey>)` send one parameter per value. SQL Server limits a command to:

| Limit                                                 | Value |
|-------------------------------------------------------|-------|
| Parameters per command                                | 2 100 |
| Rows in a single `VALUES` table-value constructor     | 1 000 |

Both methods split the list into chunks that respect these limits and return the summed row count. The chunks are separate statements, so **wrap the call in a transaction** if you need all-or-nothing behaviour. For very large lists, the `*Bulk` class (`SqlBulkCopy`) is faster. PostgreSQL `InsertAsync(List<T>)` is limited to 65 535 parameters. PostgreSQL `DeleteAsync(List<TKey>)` uses one array parameter and has no practical limit.

### Default type mappings

| CLR type                       | SQL Server         | PostgreSQL                   |
|--------------------------------|--------------------|------------------------------|
| `bool`                         | `bit`              | `boolean`                    |
| `byte` / `short` / `int` / `long` | `tinyint` / `smallint` / `int` / `bigint` | `smallint` / `smallint` / `integer` / `bigint` |
| `float` / `double`             | `real` / `float`   | `real` / `double precision`  |
| `Guid`                         | `uniqueidentifier` | `uuid`                       |
| `DateTime`                     | `datetime2`        | `timestamp`                  |
| `DateTimeOffset`               | `datetimeoffset`   | `timestamptz`                |
| `DateOnly` / `TimeOnly`        | `date` / `time`    | `date` / `time`              |
| `TimeSpan`                     | `time`             | `interval`                   |
| `enum`                         | underlying integer type | underlying integer type |
| `string`, `decimal`, `byte[]`  | rule required      | `string` → `text` (by design); `decimal` rule required; `byte[]` → `bytea` |

`uint`, `ulong`, `ushort`, `sbyte` and (on SQL Server) `char` have no default mapping. On Domain/Bulk models they are rejected with AG017 unless configured with `.Type(...)`. SQL Server `time` holds at most 24 hours; use `bigint` ticks for longer durations.

### Table naming

Without `Table("...")`, the table name is the class name, pluralized with a simple English rule:
- consonant + `y` → `ies` (`Category` → `Categories`);
- names ending in `s`, `x`, `z`, `ch` or `sh` get `es` (`Box` → `Boxes`);
- otherwise `s` is appended.

The default schema is `dbo` on SQL Server and `public` on PostgreSQL. `CreateTableAsync` does not create a missing schema. On PostgreSQL it uses `CREATE TABLE IF NOT EXISTS`, while on SQL Server it fails if the table already exists.

### Using both providers in one file

Both runtimes define `AdoGenConcurrencyException`, `BulkApplyResult`, `BulkOp` and `PropertyBuilder` in their own namespaces. With both `using AdoGen.SqlServer;` and `using AdoGen.PostgreSql;` in scope, references to these names are ambiguous (CS0104). Use aliases:

```csharp
using SqlConcurrencyException    = AdoGen.SqlServer.AdoGenConcurrencyException;
using NpgsqlConcurrencyException = AdoGen.PostgreSql.AdoGenConcurrencyException;
```

### Optimistic concurrency and missing rows

`UpdateAsync` and `DeleteAsync` on a model with a concurrency token throw `AdoGenConcurrencyException` whenever 0 rows are affected. That includes the case where the row does not exist at all. If you need to tell the two apart, check `ExistsAsync` after catching the exception.

## Limitations

- **No arbitrary SELECT generation.** AdoGen never generates arbitrary SELECT queries. `ExistsAsync` is the one exception — it emits a `SELECT TOP(1) 1` / `SELECT 1 … LIMIT 1` query. All other reads use hand-written SQL via `QueryAsync` / `QueryFirstOrDefaultAsync`.
- **`InsertAndReturnAsync` fails with certain SQL Server triggers** that cascade inserts to other tables (`OUTPUT INSERTED.*` is not supported in that scenario). Use `InsertAsync` + a subsequent `QueryFirstOrDefaultAsync` instead.
- **`PatchAsync` checks the concurrency token only when `WithExpected{Token}(...)` is called.**
- **PostgreSQL `UpsertAsync` on identity-keyed models uses `MERGE`** and requires PostgreSQL 15+.
- **Bulk operations require an explicit transaction.** `SaveChangesAsync` does not create one internally.
- **One concurrency token per model.** Only one property may be marked `.ConcurrencyToken()`.
- **Profiles are required for Domain/Bulk models.** Even if every property has a default mapping, a profile class must exist in the compilation. Mapper-only DTOs are exempt (see [Profiles](#profiles)).
- **Required profile configuration.** SQL Server needs explicit configuration for `string`, `decimal` and `byte[]`. PostgreSQL needs it only for `decimal`; strings default to `text` (see [PostgreSQL types](#postgresql-types)). Missing configuration is a compile-time error (see [diagnostics](diagnostics.md)).
- **DTO shape.** DTOs must be top-level (AG015), `partial`, non-static, non-abstract (AG014), and at least `internal`. They may be non-sealed and used as base classes; subclasses are not DTOs unless they implement a marker interface themselves.
- **Columns are settable properties.** A property is a column if it has a setter/`init` or a matching constructor parameter. Computed get-only properties (e.g. `FullName => …`) and indexers are ignored. There is no `Ignore()` for settable properties.
- **Column names must be valid identifiers** (AG016). `.Name("...")` values are used in both C# member names and SQL parameter names.
- **Unsupported CLR types** (AG017). `uint`, `ulong`, `ushort`, `sbyte` and SQL Server `char` need an explicit `.Type(...)`.
- **`ExecuteScalarAsync<T>` casts, it does not convert.** See [Scalar & execute helpers](#executescalarasynct).
